# 票根 · 支付宝小程序壳（源码）

这是票根的支付宝小程序壳，不是已发布的小程序。它只做四件事：

1. 用 `web-view` 打开票根 PWA；
2. 接受可选的 `url` 参数，但只允许 `https://`；
3. 记住上次打开的地址（只存本机），并读取系统深浅色与平台，拼进 URL 提示；
4. 网页里用户明确点“开启到期提醒”时，才请求一次订阅消息（模板 ID 留空则不请求）。

它不读取支付宝账号、手机号、卡号、余额、位置或通讯录，也不主动发消息。

## 当前状态

- **未发布**：没有 AppID、没有提交审核、没有商户号。
- **未接入支付回调**：支付后入口是 URL 参数契约，见 `../afterpay.html`。
- **订阅消息未接**：`index.js` 里 `REMINDER_TEMPLATE_ID` 为空；没在开放平台申请模板并通过审核前，不会弹订阅框。
- **没有真实用户数据**：web-view 里仍然是票根本地模式，数据只存浏览器。

## 网页 ↔ 壳的消息契约

网页在支付宝 web-view 里 `my.postMessage({ type: "subscribe-reminder" })`；壳收到后调用 `my.requestSubscribeMessage`。只在用户点击后发送，不在加载时自动请求。

壳给网页的 URL 追加 `mini=alipay&theme=dark&platform=ios` 之类的提示参数；网页可以据此隐藏“安装到桌面”等不适用的入口。

## 怎么在支付宝开发者工具里打开

1. 安装支付宝小程序开发者工具。
2. 新建项目，目录选这个 `alipay-mini/`。
3. AppID 用你自己的测试 AppID；没有就选“无 AppID / 测试”。
4. **开发预览**可在开发者工具里勾“不校验域名”；正式 web-view 业务域名必须是你自己的、已备案的 HTTPS 域名，并且你能把支付宝的校验文件放到域名根目录。`enmingxiong821-cloud.github.io` 不是你自己的域名，也不能放校验文件，**不能用于正式 web-view 白名单**。
5. 编译预览。首屏会加载：
   `https://enmingxiong821-cloud.github.io/piaogen/?from=alipay-mini`（仅开发预览）

## 上线前必须补的

- 用真实 AppID 替换测试 AppID。
- 如需到期提醒：在开放平台申请订阅消息模板，把模板 ID 填进 `pages/index/index.js` 的 `REMINDER_TEMPLATE_ID`。
- 在支付宝开放平台配置 **H5 域名**（不是服务器域名白名单），并确保域名已备案、HTTPS 有效、根目录可放校验文件；把票根静态站部署到该域名。
- 主体要求：web-view 只对企业/个体工商户主体开放；个人主体功能受限。完整清单见 `../接入清单_支付宝.md`。
- 如果要做支付后入口，申请对应能力；没有审核通过前，不要把原型写成“已接入”。
- 真机测试：iOS / Android 各一台，检查 web-view 返回键、键盘、文件选择、下载与 PWA 安装提示。

## 为什么用 web-view 壳

票根是零构建静态 PWA，已经有 15 屏、OCR、案卷、资金售后、MCP。重写成小程序原生页面会复制一套业务、增加维护成本，也会让“本地优先”的数据边界变复杂。壳方案保留了同一套代码与同一套测试，先把“支付宝内可打开”这一步做真；原生能力（订阅消息、支付后推荐位）等审核通过后再接。

## 边界

- 壳不代登录、不代提交、不代收款、不托管资金。
- 壳不读取支付宝账单；账单仍由用户在票根里主动粘贴或拍照。
- 壳不保存任何用户数据；web-view 内的数据只在本机浏览器。
