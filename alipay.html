支付宝接入面

核对日期：2026-11-25　·　只写已经能验证的接入面，不把“设计”写成“已接入”

票根不是一个孤立的网页。它把“付款之后”的五个入口都留成了可接入的接口：支付完成页跳转、小程序 web-view、支付宝账单 CSV、只读交易查询适配层、以及可被 Agent 调用的 MCP 工具。下面每一项都标明现在有什么、还缺什么、评委怎么验。

0. 现在能不能接

条件现状卡在哪
公网只读 MCP已上线不需要支付宝资质；示例数据、只读、限流。
CloudBase 托管已具备静态站与云函数都已部署。
小程序主体未满足web-view 只对企业/个体工商户主体开放；个人主体功能受限。
备案 HTTPS 域名未满足小程序 web-view 要配置「H5 域名配置」，域名需备案且能放校验文件；GitHub Pages 域名不能配。
AppID / 商户凭据未提供交易查询需要 AppID、商家 PID、RSA2 密钥与接口权限；私钥只进环境变量。
支付宝 AI 开放平台未申请目前面向企业开发者/代开发服务商邀测。

完整步骤、费用与“需要你提供什么”见 接入清单_支付宝.md。在主体、域名与凭据就绪前，这一页不会把小程序或交易查询写成“已接入”。

1. 五个接入面

接入面现在有什么还缺什么怎么验
支付后 URL 已实现参数契约 ?from=afterpay&merchant=…&product=…&amount=…&date=…&order=…；同交易号去重；案卷标“来自支付完成页”。 商户号与真实 1403 回调；没有回调时只能由支付完成页拼链接。 afterpay.html 点“看权利回执”，会带参数建案。
小程序 web-view 可编译源码 alipay-mini/：app.json、页面、web-view、只接受 https 的 URL 校验。 AppID、审核、域名白名单；没有这三项不能发布。 alipay-mini/README.md 有开发者工具步骤与上线前清单。
支付宝账单 CSV 已实现本机导入：支付宝“交易流水证明”CSV，自动识别 UTF-8 / GBK，提取时间、对方、商品、收支、金额；同一商户连续扣款会提示疑似续费。 不调用支付宝账单 API；用户需自己导出 CSV。 导入页 → 粘账单 → “选支付宝 / 微信账单 CSV”。文件不上传。
只读交易查询 适配层源码 cloudfunctions/piaogen-alipay/：RSA2 签名调 alipay.trade.query，响应验签后只回白名单字段，买家账号脱敏；只接受订单号、只读、不落库。离线自检 10 项通过。 未部署；需要 AppID、应用私钥、支付宝公钥与一个函数域名；没有凭据时返回 not_configured。 node selftest.js 可离线验证签名与裁剪；真实查询需自行部署并用自己的商户订单号。
MCP 工具 本地 stdio 七工具已跑通；公网只读端点已上线：…/piaogen-mcp，HTTP + JSON-RPC 2.0，7 个只读工具，示例数据，每 IP 每分钟 60 次。 公网端点只读，不托管用户数据；写操作只在本地。接入阿宝仍需企业开发者/代开发服务商资质与邀测。 GET …/piaogen-mcp/health 可当场验；agent-api.html 有 7 工具与示例；manifest 可机器读。

2. 只读交易查询适配层

不是“已接入支付宝”，而是把接入要写的服务端代码先写完：有商户凭据就能部署，没有就明确返回未配置。

项实现
接口POST /，body 只接受 {"outTradeNo":"…"} 或 {"tradeNo":"…"}；订单号限 [A-Za-z0-9_-]{1,64}
调用的方法只有 alipay.trade.query；没有退款、转账、关单、代扣
签名RSA2（RSA-SHA256），参数按 key 排序后签名；biz_content 用原始 JSON
响应先验签，再只保留 trade_status / total_amount / receipt_amount / refund_fee / subject / send_pay_date 等白名单字段；不返回 buyer_user_id、资金明细、券明细
隐私买家账号只回脱敏值；不落库、不写请求/响应日志；不读也不存手机号、身份证、卡号
限流单 IP 每分钟 30 次（可配置）；请求体解析失败直接 400
状态代码完成，未部署，未用真实凭据跑通；selftest.js 10 项离线通过

3. 支付后 1403 需要什么

字段用途现在
out_trade_no同一笔交易只建一次案卷URL 用 order 参数模拟；无真实回调
total_amount争议金额，不当作可追回金额URL 用 amount，只接受正数
subject / 商户名案卷标题与后续材料URL 用 product / merchant，长度受限
gmt_payment权利窗口起算日URL 用 date，格式 YYYY-MM-DD
签名与验签防止伪造回调异步 1403 回调验签未实现；alipay.trade.query 的响应验签已在适配层实现

4. 小程序发布前必须补的四项

  1. AppID：没有 AppID 无法在支付宝开发者工具里预览真机。
  2. 业务域名白名单：web-view 只能打开已备案、已加入白名单的 https 域名。
  3. 订阅消息模板：到期提醒需要模板 ID 与用户授权，不能默认推送。
  4. 隐私协议与权限说明：读取订单/账单属于敏感能力，需要逐项说明用途。

5. 为什么现在不假装“已接入”

  • 没有 AppID、商户号、私钥与回调域名，任何“已接入支付宝”的写法都无法被评委复现。
  • 票根的做法是：把接入面做成可编译、可调用、可验证的代码与契约，并明确标注未发布、未审核、尚未上线、无真实回调。
  • 这样评审核验时，能看到“接进去要改哪四个地方”，而不是看到一张无法运行的截图。
