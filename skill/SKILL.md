# 票根 · 消费权利计算

把「我这张票还能做什么」变成一份可以核对、可以照着办的回执。

## 什么时候用

用户提到下列任一情形时使用：

- 「这个还能退吗」「过了几天了」「还能换吗」「价保到哪天」「保修几年」
- 收到货不满意、商品有质量问题、想退货换货维修
- 买贵了想补差价、想知道价保有没有过
- 自动续费忘了关、被扣了钱、预付卡还有余额
- 保险刚买想退、犹豫期还有几天
- 退款一直没到、信用卡账单有争议、想拒付
- 「我该找谁」「要准备什么材料」

## 五步

1. **取字段**：商品名、金额、购买日期、签收日期（线上 7 天无理由从这天算）、发票日期（三包从这天算）、渠道（线上/线下）。
   缺哪个就只问哪个，一次问完，不要挤牙膏。
2. **算窗口**：调用 `rights.lookup`（MCP）或 `POST /piaogen-mcp/rights`（REST）。
   拿回每项权利的 `start` / `end` / `daysLeft` / `applicability` / `basis` / `basisUrl`。
3. **报结论**：先说最近关闭的那一项和还剩几天，再说其余。
   没有确定截止日的（比如价保没标识）明说「待确认」，**不倒计时**。
4. **给下一步**：调用 `rights.plan` 或 `POST /piaogen-mcp/plan`，拿到 `next` / `materials` / `official` / `doNot`。
   按「商家 → 平台 → 12315/12345」的顺序讲，不要跳级。
5. **标边界**：说清这是按官方目录和法条算的，金额与天数以票据为准；不代提交、不承诺退成。

## 输出怎么说

- **先给判断，再给依据**。第一句是「无理由退货只剩 1 天」，不是「根据《消保法》第二十五条……」
- **三级置信**：法条与起算日都确定的说「高」；有依据但缺字段的说「中」；只是推断或商家承诺的说「低」。不要把「中/低」说成「已核实」。
- **金额三口径分开**：争议金额、预计可追回、已确认解决。只有用户说钱到账了，才说「已解决」。
- **没有公开依据的天数不倒计时**，写「以合同/机构告知为准」。

## 硬边界

- 不代用户提交任何投诉、申请、退款、拒付。
- 不代收款、不托管资金、不索取完整卡号 / CVV / 验证码 / 网银密码（只要卡尾号）。
- 不承诺「保证退回」「保证拒付成功」；不做法律、金融、医疗确定性结论。
- 不做贷款推荐、保险推荐、投资建议、征信修复。
- 照片与票据不出用户本机（本地版）；公网端点只做纯计算，不存任何输入。

## 例

> 用户：11 月 20 号在京东买了个空调 3299，今天想退，还来得及吗？

```
rights.lookup {product:"空调", channel:"jd", amount:3299,
               date:"2026-11-20", receivedDate:"2026-11-20", today:"2026-11-26"}
```

回：

> 线上 7 天无理由还剩 **1 天**（11-27 截止，置信高）。三包退货 7 天、换货 15 天都还开着，保修 3 年。
> 价保要看订单页有没有标识——有的话能补差价，没有就不是法定权利，我不给你倒计时。
> 先做：今天在订单页点「申请退货」，选「7 天无理由」。带订单截图和支付记录。
> 别做：别先寄回去再申请，也别答应「换货」了事——换货会关掉退货窗口。
